# Project brief — example applicant

Example only. A fictional project. `brief` writes a real one, one per
fellowship, to `applicants/{applicant-id}/{fellowship-id}/brief.md`
(gitignored), validates it, and points you to it.

This file is the applicant's own words. `list` reads it to decide whose
published work could host the project; `summarize` reads it to say what of a
host candidate's record touches it; `recommend` reads it as the whole of what
`fit` is judged against. It is the one file in the repository that nothing
validates the prose of, because a project description is not a controlled
vocabulary.

Write it in your own language. Only the question is needed: a few sentences,
or a CV or a proposal `brief` can read it from. What you would do is optional.
Where you state no needs, `brief` drafts two to four from the question and the
fellowship's rules for you to accept or edit, and the line under them says so.
A page is plenty.

## The question

Example question: whether an example circuit implements an example computation,
and if so by what mechanism. The current models account for the steady state and
not for the transient, and no published recording set is long enough to separate
the two.

## What I would do

Optional. Example plan: extend the spiking model of the circuit to the transient regime,
fit it to long-duration recordings, and test the mechanism against an
intervention the model predicts should abolish it. The modelling half is mine
already; the recordings are not.

## What I would need from a host

*Drafted from the question and accepted by the applicant on 2026-09-22.*

- Example need: long-duration recordings from this circuit, by a group whose
  own question is the transient rather than the steady state.
- Example need: a group that would run the intervention the model predicts as
  its own experiment rather than as a favour.
